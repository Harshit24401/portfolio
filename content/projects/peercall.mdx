## Problem / context

PeerCall began as a Next.js and Firebase prototype for one-to-one calls. I wanted real group calls and an app I'd trust other people with. That meant understanding WebRTC signaling properly, not copying it, and making the backend hold up when the network and the clients misbehave.

## What I built

A group video-calling app. You sign up, add friends, and call them directly or share a call link. Everyone in a call sees everyone else. It has presence (who's online), chat, friend requests and direct call invites, and someone who joins late still connects to everyone already in the call.

I rebuilt the prototype as a React (Vite) frontend, an Express backend with a raw WebSocket signaling server, and Supabase (Postgres and Auth) for accounts and call state.

## How it works

    'Backend verifies the sender, relays to the target, and saves the signal to Supabase',
    'Late joiner: replay the saved signals they missed',
    'Media flows peer-to-peer (STUN, with TURN relay when NAT blocks it)',
  ]}

**Full mesh.** Every browser tab holds one peer connection per other participant, so audio and video go directly between people and the server only carries signaling. For small calls that's simple and cheap. It also means each person uploads their stream once per other participant, which is the limit on call size.

**Signals saved for replay.** Every offer, answer and ICE candidate is saved in a `peer_signals` table as well as relayed. Someone who joins a moment late is replayed what they missed, instead of the call silently failing to connect.

**Getting through NATs.** STUN covers most networks. For the rest, TURN relays the media: a self-hosted coturn server, with the free Open Relay Project as an interim fallback.

## Results or aim

- **80+ automated tests** (`node:test`) for the REST API and the WebSocket signaling, run against a real Supabase test database.
- **An authorization bug, found and fixed.** The call-decline handler trusted the caller id sent in the message, so any signed-in user could end anyone's call and send a forged "declined" notice to anyone. Now the declining user comes from the socket's verified token and the caller comes from the database. A decline from someone outside the call is ignored.
- **Declined calls stay declined.** A rejoin path meant for dropped tabs could also revive a declined call for anyone holding its id. A new `declined` state is refused with close code 4403.
- **A silent failure surfaced.** Every "restart ICE" request had been failing to save, and the error was thrown away. It's now relayed without being saved, and the other saves check their errors.
- **Presence that recovers.** After a laptop sleep or a Wi-Fi blip, the presence socket used to stay dead, so friends saw you offline and calls never arrived. It now reconnects with exponential backoff (1 s up to 30 s) plus jitter, so many clients don't all retry at once after a backend restart.
- **Errors that are always JSON.** Bad ids and query parameters are rejected with a 400 before they reach Postgres. Unknown routes and thrown errors return JSON instead of an HTML page the frontend couldn't parse.

## What I'd do next

- Move from full mesh to a media server (an SFU) so calls can grow past a handful of people without everyone's upload bandwidth running out.
- Finish moving TURN fully onto the self-hosted coturn server and retire the public fallback.
